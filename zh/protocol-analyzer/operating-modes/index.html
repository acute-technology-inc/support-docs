    操作模式

    设置内存用量、停止条件与重复采集行为。

    内存设置

    控制采集协议数据时使用多少内存。

    设备内存用量

    设备内存上限：

    • 未勾选： 使用可用的最大设备内存
    • 勾选： 内存使用比例可调整
    • 可限制内存以加快后处理
    • 不需要完整内存时很有用

    注意事项：

    • 内存越多＝采集时间越长
    • 内存越多＝采集后处理时间越长
    • 内存越少＝处理与显示越快

    触发位置

    设置内存中前触发数据与后触发数据的百分比。

    示例：

    • 0%： 全部内存用于后触发数据（无前触发）
    • 20%： 20% 前触发、80% 后触发
    • 50%： 前后触发数据相同
    • 80%： 80% 前触发、20% 后触发
    • 100%： 全部内存用于前触发数据（触发点在结尾）

    使用场景：

    • 0–20%： 采集触发事件之后发生的事
    • 50%： 均衡查看触发前后的活动
    • 80–100%： 采集导致触发事件的过程

    停止条件

    设置采集何时自动停止。

    数据行数

    保存的数据行数达到指定数量时停止采集。

    设置：

    • 启用： 设置目标协议事务／数据包数量
    • 停用：（默认）采集到内存填满或手动停止

    使用场景：

    • 需要特定数量的事务（例如 1000 个 I2C 数据包）
    • 避免不必要的长时间采集
    • 多次运行时测试数据量一致
    • 以固定数据包数做自动化测试

    优点：

    • 已知需要多少数据时采集更快
    • 避免浪费时间采集超过所需的数据
    • 数据量可预测时简化后处理

    设备内存上限

    设备内存填到指定上限时停止采集。

    默认行为： 所有模式均启用

    各采集模式的效果：

    • Protocol Analyzer： 内存满时设备停止
    • Protocol Logger： 达到磁盘空间上限时停止
    • Protocol Monitor： 设备内存满时停止（或符合触发条件时）

    重复采集

    自动重复采集多次。

    重复次数设置

    停用（默认）：

    • 符合停止条件一次后设备即停止
    • 每次 Start 命令执行一次采集

    启用：

    1. 设备采集到符合停止条件
    2. 保存采集的数据
    3. 自动开始下一次采集
    4. 重复指定次数

    设为 0： 连续重复采集（无限循环）

    • 持续采集到手动停止
    • 每次采集分别保存
    • 适合长期监控

    重复采集行为

    控制重复采集期间的波形解码。

    选项：

    1. 不显示解码： 采集较快，稍后分析
    2. 按间隔显示： 选择显示时间
    3. 1 秒
    4. 2 秒
    5. 5 秒

    取舍：

    • 不显示＝采集速率最快
    • 显示＝较慢但提供实时反馈

    各模式专属设置

    Protocol Analyzer 模式

    内存考量：

    • 受 RAM 与设备内存限制
    • 实时处理使用较多资源
    • 电脑性能影响采集可靠度

    停止行为：

    • 若电脑跟不上数据率，可能自动停止
    • 采集期间监控内存用量
    • 若发生自动停止，降低采样率

    Protocol Logger 模式

    内存考量：

    • 受硬盘空间限制
    • 可采集非常长的时间
    • 处理时间与采集大小成正比

    额外选项：

    采集停止后执行数据处理：

    • 勾选： 停止后自动处理 .LOG 文件
    • 立即分析

    • 停止时间较长

    • 未勾选： 仅保存 .LOG 文件

    • 停止较快
    • 稍后手动打开 .LOG 文件再分析
    • 适合非常大量的采集

    Protocol Monitor 模式

    内存考量：

    • 仅受设备内存限制
    • 某些设置为环形缓冲区
    • 固定的最大数据量

    等待模式：

    等待停止（Wait for stop）

    采集持续到按下“Stop”为止

    • 内存填入最新数据
    • 内存满时覆写旧数据（环形缓冲区）
    • 准备取回数据时按 Stop
    • 一律取得最近的活动

    使用场景： 采集系统故障或用户操作之前的时刻

    等待触发（Wait for trigger）

    采集持续到符合触发条件为止

    未设置触发条件时：

    • 没有前／后触发关系
    • 采集到内存填满
    • 基本上等同于没有环形缓冲区的“等待停止”

    已设置触发条件时：

    三种触发后选项：

    1. 填满设备内存再停止
    2. 依触发位置百分比
    3. 采集最多数据

    4. 填满所有可用内存

    5. 立即停止

    6. 触发一发生即停止
    7. 反应最快
    8. 数据量较小

    9. 只在意前触发数据时很有用

    10. 等待数秒再停止

    11. 触发后的时间长度可设置
    12. 在即时性与数据完整性之间取得平衡
    13. 若内存先填满则提前停止

    提示与最佳实践

    选择内存设置

    使用完整内存的时机：

    • 不确定需要多少数据
    • 采集偶发问题
    • 想要最多数据

    限制内存的时机：

    • 明确知道需要多少数据
    • 快速后处理很重要
    • 计划做多次重复采集

    重复采集策略

    重复采集适用于：

    • 压力测试（多次采集相同场景）
    • 检测偶发问题（采集到问题出现）
    • 统计分析（收集多份样本做平均）
    • 长期监控（整夜连续采集）

    流程示例：

    1. 将重复次数设为 100
    2. 将停止条件设为 1000 个数据包
    3. 开始采集
    4. 系统自动采集 100 × 1000 个数据包的数据组
    5. 分析所有采集结果找出异常

    停止条件组合

    快速、已知大小的采集：

    • 启用“数据行数”
    • 设为所需的数据包数
    • 停用内存上限（或设得很高）
    • 结果：刚好采集所需数据，并快速停止

    长时间监控：

    • 停用“数据行数”
    • 使用 Protocol Monitor 的“等待触发”
    • 设置合适的触发条件
    • 结果：以触发式采集进行有效率的长期监控
